## Structured Notes

### Core Technique
A procedural "3D printer" rig built entirely in Geometry Nodes: a spline traces across a mesh's per-island UV map and progressively deforms/reveals the surface along it, faking a live tissue-printing/growth process. Same tracer+deform system drives two interchangeable outputs — a filled surface or discrete "muscle fiber" strands — and is applied first to a generic blob, then to hand tendons and muscles built over a skeleton reference mesh.

### Summary
The rig has three decoupled parts: (1) **Printer Tracer** — the source mesh is split into square-ish per-UV-island maps; a spline samples across each island (Sample Nearest Surface, chosen over Sample UV Surface for its error tolerance) and interpolates between islands with a custom easing node group; (2) **Print Deform** — samples the tracer's curve to get a progress fraction + Group ID per island, then mixes the surface between its flat and printed position, raised along its normal while printing; (3) a purely cosmetic **printer-head** instance that rides the tracer transform via an Empty (can be deleted with zero effect on the actual print). Materials fake an iridescent print bead using three overlapping colored spotlights (a workaround since EEVEE doesn't yet support gradient/textured lights).

Midway through, the streamer switches to a hand-anatomy piece (skeleton reference → tendons → muscles) and hits a genuinely useful **Cycles-only bug**: naming a Store Named Attribute output `UV` silently gets ignored by Cycles renders (EEVEE was fine) because it collides with Blender's reserved active-UV-map attribute name — same class of collision can happen with names like `color`. Fix used: rename the attribute away from the common/reserved name (streamer used a distinct capitalized variant) everywhere it's produced and consumed.

Also demonstrated: an ad-hoc **auto-square-UV** technique (no add-on) that gets around manually running Follow-Active-Quads on a subdivided quad mesh — derive X/Y gradients from shortest-edge-path distances to two mesh boundary edges, normalize each with Field Min/Max, use that as a synthetic square UV. Not fully general (doesn't account for edge length or all topologies) but sufficient for this quad-subdivided anatomical mesh.

### Key Steps
1. Split base mesh into UV islands (retopologized so each island is roughly square).
2. **Printer Tracer** group: sample a spline across the active UV island (Sample Nearest Surface by Island Index + Group ID, shifted by time); interpolate between the current and next island's spline via a custom easing node group (two offset splines, mixed).
3. Store the traced transform; raise it above the surface along the stored normal while printing, settle back down between transitions.
4. Transfer the traced transform from a spline instance onto an Empty (via Sample Index / instance-transform) so external objects (e.g. a rigged printer arm) can parent to the print point without living inside the node tree.
5. **Print Deform** group: sample the tracer curve's first point for Group ID + progress fraction; mix each vertex between its flat and printed position based on whether the deform's own island/progress has been reached ("printed yet or not").
6. Switch group-input toggles between filled-surface output and discrete muscle-fiber-strand output (mesh, not curves) — both driven by the same UV/Group-ID data.
7. For anatomical parts: auto-square the UVs via the edge-path-gradient trick (see below) instead of manual Follow Active Quads, when the mesh is subdivided/irregular.
8. Consolidate: fold the Group-ID-prep step into a small reusable "prep" node group run once on the source geometry (self object + template object override), so Tracer/Deform/Muscle all read the same prepped attributes instead of recomputing them separately — collapses what was originally several duplicated objects/graphs into one.
9. Add an auto-stop: Attribute Statistic on Group ID → max island count → clamp the time-driven progress against `island_count + 0.5` (Smooth Minimum) so the animation halts instead of wrapping back to 0.
10. Store a dedicated custom-normal attribute for the printed-fiber mesh (separate from the base mesh's own normals) — needed once fiber geometry is joined with other objects, or shading breaks.
11. For fiber/tendon materials, UV-unwrap with **Minimum Stretch weight = 0** to force a near-circular UV island (better for cylindrical materials than the default relaxation).

### Nodes / Settings
- Sample Nearest Surface (preferred over Sample UV Surface — more error-tolerant)
- Store Named Attribute (custom Group ID, custom Normal, custom UV — **avoid reserved/common names like `UV` or `color` when the target is rendered in Cycles**, they silently collide with internal attributes)
- Custom "Easing" node group and custom "Curve to Measure UV" node group — both free assets on the author's Gumroad (gumroad.com/bbbn19)
- Shortest Edge Paths (×2, for the X/Y auto-square-UV gradient trick) + Field Min/Max or Map Range to normalize
- Attribute Statistic (max Group ID → auto-stop threshold)
- Sample Index / instance-transform pattern (transform data → Empty, for external rigging)
- Face-corner 2D-vector UV Unwrap with Minimum Stretch weight set to 0 (circular UV) or ~10 (mild relaxation)
- Transfer Attribute node — mentioned as the modern, more flexible superset of Sample Index for topology-changing transfers
- 3 overlapping colored spotlights for an iridescent print-bead look (EEVEE workaround for lack of gradient/textured light support)
- Aside: Blender 5.2/5.3 Raycast node gained a visibility/ray-visibility option; XPBD cloth solver can approximate muscle simulation but currently lacks self-collision, which the streamer notes is limiting for overlapping muscle geometry (comparison to Houdini Vellum).

### Difficulty
Advanced — heavy custom Geometry Nodes graph engineering (multi-group data plumbing, UV/attribute bundling across decoupled tracer/deform/muscle groups) plus a non-obvious Cycles internals gotcha. The auto-square-UV and progress-auto-stop sub-tricks are intermediate and usable standalone.
